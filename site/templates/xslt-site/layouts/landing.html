Find out what breaks

One command scans a project for the XSLT it runs in the browser: pages that call XSLTProcessor, XML documents rendered with <?xml-stylesheet?>, and the stylesheets themselves. Nothing leaves your machine.

npx xslt-migrate-check .

Found 5 XSLTProcessor usages in 2 files
Found 12 XSL stylesheets (10 × XSLT 1.0, 1 × XSLT 2.0, 1 × XSLT 3.0)
Found 3 XML documents rendered with <?xml-stylesheet?>
Chrome compatibility risk: HIGH
Suggested migration: @tradik/xslt-processor

It ends with the one line that fixes each kind of page: a <script> tag for pages that use XSLTProcessor, and the same tag inside an XML document for <?xml-stylesheet?>. Add --fail-on high in a pipeline. The migration how-to walks through every step; the reference lists what it looks for.
